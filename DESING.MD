# Real-Time Object Segmentation & Description System

## Project Overview

A web application that streams live video from a mobile device to a Python/x86 backend server with GPU support, enabling real-time AI-powered object segmentation (SAM-3 via TensorRT) and natural language description (PaliGemma) overlaid directly on the live feed.

---

## Architecture Overview

```
Mobile Browser  ──RTSP/WebSocket──▶  MediaMTX (media server)  ──▶  Python Backend (GPU)
     │                                                                     │
     │  ◀──────────────  Processed video stream (WebSocket) ──────────────┘
     │
     ├── Camera feed → RTSP stream (outbound)
     └── Processed overlay stream (inbound, rendered canvas)
```

### Components

| Layer | Technology |
|---|---|
| Frontend | Web app (mobile browser) |
| Media relay | MediaMTX (RTSP server) |
| Backend | Python, x86 with GPU |
| Segmentation model | SAM-3 (via TensorRT) |
| Description model | PaliGemma (via TensorRT) |
| Transport | WebSocket + RTSP |

---

## System Lifecycle

### 1. Server Startup
- The Python backend starts and loads all models into GPU memory:
  - **SAM-3** (via TensorRT) — object segmentation
  - **PaliGemma** — visual description generation (via TensorRT)
- The server enters an idle state, listening for incoming WebSocket messages and action events.

### 2. App Initialization (Mobile)
- The user opens the web app on their mobile device.
- The app requests **camera permission** from the user.
- Upon approval, the app starts an webRTC of the camera feed to the MediaMTX server via WebSocket.
- Simultaneously, the app subscribes to an **inbound processed stream** — the backend's annotated output — and renders it on screen (replacing or overlaying the raw camera view).

---

## User Actions & Interactions

All interactions are event-driven. Each action sends a message to the backend via WebSocket.

### Action 1 — Grant Camera Permission & Start Streaming
- Trigger: User taps "Allow" on the camera permission prompt.
- Effect: App begins streaming camera to MediaMTX; app subscribes to the processed output stream.

### Action 2 — Draw a Region of Interest (ROI)
- Trigger: User **touches and drags** on the video canvas to draw a bounding box.
- Effect: A rectangular ROI is drawn on screen. The coordinates (normalized to `[0.0, 1.0]` range for both axes) are sent to the backend as a bounding box message.
- Purpose: Defines the area containing the object to segment.

### Action 3 — Start Segmentation & Tracking
- Trigger: User **taps on an existing bounding box**.
- Message sent: `{ action: "segment", bbox: { x1, y1, x2, y2 } }` (relative coordinates, range 0–1).
- Effect: Backend runs SAM-3 inference on the region and begins tracking the segmentation across subsequent frames.

### Action 4 — View Object Description (Pop-up)
- Trigger: User taps the **"+" icon** displayed at the corner of the active segmentation mask overlay.
- Effect: Opens a pop-up panel containing:
  - A cropped view of the segmented object.
  - An AI-generated text description of the object (from PaliGemma).

### Action 5 — Close Description Pop-up
- Trigger: User taps the **"×" (close) button** in the top-right corner of the description pop-up.
- Effect: Pop-up is dismissed; the live segmentation overlay remains active.

## Backend Processing Flow

### Object Segmentation (SAM-3 + TensorRT)

1. Backend receives a WebSocket message: `{ action: "segment", point | bbox }`.
2. SAM-3 (TensorRT-optimized) runs inference on the current video frame using the provided prompt.
3. The segmentation mask is rendered as an overlay on top of the live video stream.
4. The annotated stream is pushed back to the client via the processed stream channel.
5. On subsequent frames, the object is **tracked** and the mask is updated continuously.

### Object Description (PaliGemma + TensorRT)

1. Triggered when the user opens the description pop-up (Action 4).
2. The backend sends to the PaliGemma API in parallel:
   - The **cropped segmentation region** (masked object).
   - The **current full video frame** (context).
3. PaliGemma generates a natural language description of the object.
4. The description is sent back to the client as a WebSocket message.

---

## Frontend Display Logic

### Live View
- The processed video stream (with SAM-3 overlay) replaces or composites over the raw camera feed.
- The overlay includes the segmentation mask and a **"+" icon** anchored to a corner of the mask bounding box.

### Description Pop-up
- Displayed when the user taps the "+" icon.
- Contains:
  - **Segmented object image** — cropped region from the current frame, masked.
  - **Description text** — generated by PaliGemma.
- Dismissed via the "×" button.
- Loading state shown while waiting for the PaliGemma response.

## Message Protocol (WebSocket)

### Client → Server

| Event | Payload |
|---|---|
| `stream_start` | `{}` |
| `draw_bbox` | `{ x1: float, y1: float, x2: float, y2: float }` |
| `segment_object` | `{ bbox: { x1, y1, x2, y2 } }` |
| `request_description` | `{ frame_id: string }` |

> All coordinates are **normalized floats in range [0.0, 1.0]** relative to the video frame dimensions.

### Server → Client

| Event | Payload |
|---|---|
| `overlay_stream` | Processed video stream (WebSocket/RTSP) |
| `description_ready` | `{ text: string, segment_image_url: string }` |
| `tracking_update` | `{ mask_bbox: { x1, y1, x2, y2 } }` |

## Key Design Constraints

- **GPU required** on server for TensorRT inference.
- **Latency**: The overlay stream should minimize round-trip delay; TensorRT is used specifically for low-latency inference.
- **Mobile-first UI**: All touch interactions (tap, drag) must be optimized for mobile screens.
- **Relative coordinates**: All positional data transmitted between client and server uses normalized `[0.0, 1.0]` coordinates to be resolution-agnostic.
- **Parallel inference**: Description generation (PaliGemma) runs independently of the segmentation/tracking loop to avoid blocking the video pipeline.

---

## Out of Scope (v1)

- Multi-object simultaneous tracking.
- Offline / on-device inference.
- User authentication.
- Session persistence or history.
